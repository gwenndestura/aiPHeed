# Quarterly pipeline audit (E24)

**Code under audit:** `backend_dev/app/quarterly/` (the isolated E24 copy), the CLI `backend_dev/scripts/quarterly_update.py`, and the config `backend_dev/config/`.

The same E23 code also sits uncommitted in `aipheed-backend-aligned/app/quarterly/`; see `BUG_FIXES.md` §0.

## Requirement → implementation → verification

| Requirement | Implementation | Verified by |
|---|---|---|
| File-level authorization + hash verification | `registry.Registry.register` computes the SHA-256 from the bytes. `SourceEntry.verify()` re-hashes. An unauthorized source → `BLOCKED`, and its content is never read. | `test_registry_hashes_and_vintages`, `test_unauthorized_source_blocks` |
| Provenance + original publication timestamps | Each registry entry records the observation period, `available_at`, `retrieved_at`, the authorizer and a reference. News eligibility uses **only** the original publication time converted to Asia/Manila. Undated news → quarantined. | `test_news_classification_by_publication_time_only`, `test_retrieval_date_never_assigns_a_quarter`, `test_quarter_of_publication_uses_philippine_time` |
| Schema, duplicate, conflict, completeness checks | **New in E24:** `validation.check_table` (missing columns, duplicate keys, conflicting values, province × quarter gaps reported as MISSING, never zero) and `completeness.province_quarter_matrix` | `test_check_table_flags_duplicates_conflicts_and_gaps`, `test_completeness_reports_missing_not_zero` |
| NLP scoring and topic processing | **New in E24:** `nlp_stage.build_news_features` runs on ELIGIBLE articles only. It calls the approved scorer (injected; production = XLM-RoBERTa zero-shot), the 0.30 relevance gate, `bias_weighter.compute_bias_weights`, `fssi_builder.compute_fssi` and `trigger_classifier.classify_triggers`. Provinces without articles get FSSI = null + LIMITED_SIGNAL. **BERTopic topic shares are not recomputed per cycle** (the model needs the full corpus, which is not authorized); this is listed as a remaining gap. | `test_nlp_stage_uses_only_eligible_articles_and_flags_limited_signal`, `test_nlp_stage_relevance_gate` |
| Forecast-origin and quarter-cutoff validation | `config.ForecastPeriod.validate()` rejects a cutoff before the reference quarter or inside the target quarter. The news window ends at min(cutoff, quarter end). An early cutoff marks the quarter incomplete. | `test_cutoff_inside_target_quarter_is_rejected`, `test_early_cutoff_marks_quarter_incomplete`, `test_cutoff_excludes_later_reference_quarter_news` |
| Model and feature versioning | **New in E24:** `validation.model_version_record` (model SHA-256, feature-list hash, trained-through quarter, protocol hash, selection rule), to be registered as a `model` source and copied into each forecast record | `test_model_version_record` |
| Reproducible forecast archives | `update.write_record`: content-hashed record. An identical rerun creates no new history entry; earlier versions go to `history/`. Inputs are snapshotted by hash (`SnapshotStore`). | `test_full_update_ready_and_consistent`, `test_snapshot_ingest_is_idempotent` |
| API / dashboard sufficiency states | `GET /api/v1/quarterly/forecast-period` serves the same record. The dashboard shows the status, the missing inputs and "Goal NOT met"; a missing forecast is never rendered as zero. | `test_api_router_serves_the_same_record`; vitest `e24.test.tsx` (jsdom render) |

Stale data is never relabelled. | `test_stale_and_late_indicators`, `test_missing_news_gives_insufficient_not_a_forecast`, `test_registry_hashes_and_vintages` |
| Quarterly transition | `ForecastPeriod.advanced()` / CLI `advance` | `test_transition_2027q1_to_2027q2` (synthetic fixtures in tmp only) |

## Findings

1. **The 2027-Q1 record is correctly `INSUFFICIENT_DATA`** (`backend_dev/data/quarterly_runs/2027-Q1/forecast_record.json`). Missing:
   - authorized 2026-Q4 news;
   - 2026-Q3 government data, CPI and the SWS round (protected);
   - a promoted model;
   - and the cutoff has not passed.

   **No Q3 news is substituted.** Zero articles are shown.
2. **No model is registered as promoted.** E24-F did not meet the acceptance criteria (FINAL_REPORT), so the requirement stays MISSING by design.
3. **Topic modelling per cycle is not wired.** BERTopic needs a model fitted on the corpus, and the corpus is not authorized for E24. Gap recorded; the existing topic shares end at 2025-Q4.
4. **Provincial CPI availability times are proxies.** The registry records retrieval time as an upper bound. Exact RSSO IV-A release dates are pending (DATA_ACQUISITION_REGISTER P6).
5. **The served API was not run** (its startup reads `aipheed.db` and models, which are hash-only). The new endpoint is tested in isolation.
