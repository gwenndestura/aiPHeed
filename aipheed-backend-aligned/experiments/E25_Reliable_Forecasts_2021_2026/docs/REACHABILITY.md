# Reachability analysis (baselines only, computed before any model was fitted)

`runner/reachability.py` -> `runs/reachability.json`. A PERFECT forecaster is assumed (every row right, probability 1 on the true class). The p-values are exact one-sided sign-flip p-values over forecast dates.

**Why scoring probabilities cannot rescue the comparison with 0/1 persistence.** On a date where naive persistence is right, its loss is 0 under accuracy, Brier, log score or any other proper rule. A perfect model can only tie there. With m dates on which persistence errs, the best p is 2^-m whatever the metric: 0.0625 for m = 4, 0.031 for m = 5.
